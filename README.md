## 开始使用

**在线版**：用浏览器打开分享给你的链接。

**本地版**：双击 `index.html` —— 单文件、零依赖、不用装任何东西、断网也能用。

⚠️ **iPhone 用户请务必「分享 → 添加到主屏幕」，从桌面图标进入。**
在 Safari 里连续 7 天不打开，系统会清掉浏览器存储里的笔记。

你的笔记只存在你自己的设备上，不上传。换设备用顶栏「导出 / 导入」搬 .json。

## 它是什么

我们不做"更好用的备忘录"。记录这件事，手机自带的备忘录做得比我们好——系统级、零启动、全平台同步，那个比较我们必输。

我们只做一件事：**把已经发生的事，变成看得见的东西。**

## 两个模块，两张图

不是因为功能多，是因为**这两种关系的拓扑根本不同**。

| | 知识模块 · 星河图 | 点滴模式 · 线索图 |
|---|---|---|
| 记的是什么 | 世界给了你什么 | 你怎么回应 |
| 性质 | 吸收 · 客观 · 可共享 · 有对错 | 感受 · 主观 · 私密 · 无对错 |
| 要看见的是 | **结构**：概念怎么连、哪里有洞 | **过程**：怎么长、怎么断、怎么收 |
| 关系的类型 | **空间性**（同时存在，谁连着谁） | **时间性**（先后发生，怎么长怎么断） |
| 所以是 | 星河 | 藤蔓 / 线索 |

**一张图装不下两种拓扑。** 硬装就是我们踩过的"通道超载"。

### 为什么偏偏是"星河"和"藤"——它们跟"河"什么关系

概念一共就三块：**土壤 → 水流 → 河流**。两个模块观察的都是**水流**，只是关注的视角不同：

- **知识模块更注重：知识点识别、融合、贯通** —— 看水流汇成了什么形状，那是**河**。拉远是一整条**星河**，拉近是**河网**（滑块上这两个词会自己切换）。
  *星河本来就是河*：银河、天河、星汉，中文里它一直是河。而且真实河网和星系本来就是同一种形状 ——
  从一个中心往外分叉、越分越细。Horton-Strahler 量的就是这个形状，血管、树杈、闪电也是同一套。
- **点滴模块更注重：事物的相互关连，提供新的观察角度** —— 看每一条水自己还在不在流，那是一条条**藤**。
  河是很多条水*汇在一起*之后的样子；这里要分开看每一条，所以是一丛往上爬的藤。
  *藤和土是同一套*：你那片土壤（反复写到的人、地方、事）里，长出这些藤。

**三块各自的解释**（左栏骨架「土壤 水流 河流」里也写了）：
- **土壤**：在点滴模块中，你提到过的那些人、那些地方、那些事，共同见证你的来时路 —— 都是你的土壤。
- **水流**：所有保存下来的信息，不管存在哪个模块，我们都认为是水流，水流为知识的构建、生长的样子提供形状。
- **河流**：水流的汇集、融合、分叉都会形成河流，我们让你看见各种形态。
- **河历** = 水流日常产生的动态描述　·　**河形** = 水流与时间共同作用下搭建成河的形状　·　**河志** = 河流中发生过的大事。

所以不是三套比喻在打架，是**同一条水，两个尺度、两种看法**。

### 点滴模式 · 线索图（当前原型）

纵向是时间，旧在下、新在上——像俄罗斯方块落下，也像地层沉积。**结晶是往下沉的，往上长是"进度"的隐喻，而"进度"恰恰是我们要拆的东西。**

- 一格 = 某段时间 × 某个要素（人 / 地点）
- 格子色相 = 是谁；格子深浅 = 这段时间出现得多不多
- 藤蔓 = 一条线索：茎是它的走向，叶是"这是植物"的记号，花是结果
- **花只有两种样子**：花苞，和开了的花。AI 判的和你确认的，长得一模一样
- 撤掉一朵花，它退回花苞，AI 以后不会再替你开这一朵

## 为什么没有"纯记录"模式

**因为客人不缺记录的地方。** 更硬的理由是定位：如果我们宣传"AI 帮你读懂"，同时又提供一个"你也可以不要 AI"的选项——那是在自己的宣传页上打自己脸。

而且没有可视化的模块，会稀释"看见"这个动词。内容进来看不见，它就从产品叙事里掉了出去——对客人价值为零，对我们成本不为零。

**但砍掉模式不等于砍掉输入框。** 差别在"记完能不能当场看见它结晶"。所以第一次进来的引导不应该是"选个模式"，而是：**记一句，然后当场看见这一句被怎么读懂了。** 用反馈代替说明书。

## 三条设计纪律

1. **能点回原句** —— AI 说的每句话都能一路点回它依据的原文。做不到这点的功能，我们不做。
2. **能撤，且撤掉是终态** —— 不会换个措辞再猜一遍。
3. **一个通道只说一件事** —— 颜色、形状、线型、位置，每个只编码一个维度。这条我们踩过三次坑，每次都是砍，不是调参。

## 当前状态：原型（务必先看这一条）

仓库里现在放的是**可视化原型**，不是可用产品。三点必须说清楚：

1. **数据是生成的假日记**，不是真实记录；
2. **"AI 判断"目前是一条规则，不是大模型** —— 判据是"这件事之后你还有没有再提过它"，公开写在上面那份说明里；
3. **存储很脆弱**：只有 `原型.html` 接了浏览器自带的本地存储，清缓存、换浏览器、换电脑就没了。没有账号，没有云同步——所以也没有人替你备份。

原型的目的只有一个：**把"看见"这件事到底长什么样，先画出来看清。**

**图读的都是这批真数据，不是写死的** —— 自己删几条，图会跟着变。

### 两条锁死的规矩（写进界面，也写进代码）

1. **模块只有两个：知识模块、点滴模块。** 文件夹树的最上层就这两条，加不了第三个；
   它们下面怎么分层、叫什么，全是使用者的自由。
2. **两个模块各走各的路。** 存下来有两个入口；日历分两块（不同底色）；
   只有知识模块会识别知识点、会等你点头确认 —— 点滴模块只按时间排着，不拿"今天有点难过"去考人。

### AI 在这个产品里只干两件事（对外口径）

| 名字 | 干什么 | 谁来干 |
|---|---|---|
| 识别 | 从已存下的东西里找出「像知识点的句子」，**摆出来等你点头** | 真模型（没接就是本机规则） |
| 连接 | 把信息流中分布在两处、但代表同一种概念的事物连起来 | 本机规则 |

**通水不靠答题，靠你点头。** 在详情里对一条候选点「算，记下」，它就通水、在星河里亮起来——我们不出题考你，也不替你判断"记住没记住"。

**第四件「判」（判定你这条说中没说中）永不实现**，V24 起整个取消而非延后 —— 这条连同
"命中率／级数／水浑归脚本不归模型"都属于**内部机制，不写进 C 端界面**：摆上去只是增加阅读压力。
界面上只留两行；「只有这两件事」这件事由标题"**能干的两件事**"自己说出来，不再另写一段解释。

### 升格：把点滴里的一句，另起一条放进知识模块

入口 = 点滴模块的列表行右键 →「挑一句升格成知识…」，弹窗列出这篇里够格的句子（8~60 字），挑一句即可。

🔴 **是"另起一条"，不是"复制"。**

- 原篇留在点滴模块，**一个字不动**（家也不变）
- 你挑的那一句在知识模块里**另起一条新记录**，自己有 id、有自己的家、能长知识点、会进星河
- 新记录只记一个 `fromId`：它是从哪篇来的

一份是**出处**，一份是你挑出来**单独看的** —— 是两个东西，不是一个东西放两处。
复制会让两份各自漂移、最后分不清哪个是真的；另起一条不会：两条各有各的家，改哪条都不影响另一条。

三处看得见痕迹：列表行两侧的土色标签（`已升格 N 句` / `来自「…」`）、详情页顶部的提示条（两侧都能点回对面）、河历两笔（`升格成知识` 在知识模块那一侧，`有一句升格走了` 在点滴那一侧）。

同一句升两次会被挡住。升格后如果挑不出知识点（那句没有知识味），会明说"升格只管把它送过去，不管它有没有知识点" —— 不假装发生了什么。

### 拖拽：一次只搬一件，且只在同一个模块里搬

| 拖什么 → 放到哪 | 结果 |
|---|---|
| 列表里的一篇 → 某个家 | 归到那个家（列表行的把手在标题区，按钮区照常点） |
| 列表里的一篇 → 模块根 | **无分类**，归为无分类（仅保留基础数据，不参与整体计算） |
| 一个家 → 另一个家 | **并进去** —— 会先问一句「它俩是一回事吗」，因为并了那个家就没了 |
| 一个家 → 模块根 | 提到这一层（等于取消上一次并家） |

三条守着的规矩：

1. **只在同一个模块里搬。** 知识模块的东西落不进点滴模块的家 —— 落点会变红，落下时把原因说出来。
2. **并家必须你点头。** 并进去等于你亲口说"它俩是一回事"，这句话它不敢替你说；并完会在「我的土壤」里自己长一条。
3. **原话一个字都不动。** 搬的只是归属，不是内容。

技术上：`dragover` 阶段读不到 `dataTransfer` 的内容（浏览器故意不给），所以拖拽数据走 `DRAG` 全局变量，事件里只带一个 id 兜底。

### 窄屏：三档，中间那档是补出来的

断点就是一条"屏幕宽度门槛"：跨过它，页面换一套排法。

| 宽度 | 排法 | 实测（窗口 1100 / 1000） |
|---|---|---|
| ≥1150px | 两栏：左 330 + 中 1012（原样） | — |
| **941–1150px** | **左栏收到 260**，左栏分区只展开「水流分类」 | 中栏 686→**760**、586→**660**（多拿回 74px） |
| ≤940px | 堆成一列（左栏在上、中栏在下） | — |

左栏**不藏起来** —— 藏了等于把导航拿走，只是从 330 收到 260。屏幕每窄一点，原来是从中栏身上一刀一刀割（中央大屏和两张图会先垮），现在左栏先让一步。

两条关于"不跟人过不去"的规矩，写进了 `syncNarrow()`：

1. **只在跨过断点那一刻收一次。** 你在中间档里手动展开了「河形」，再拖一下窗口它不会自己合上。
2. **变宽时不自动展开。** 展开什么是你的事，它不替你决定。
3. 「家」永远留着 —— 那是导航本体，不是概览。

手机（≤768px）做成可呼出的抽屉是另一件事，成本大得多，**暂不做** —— 这产品的第一场景是书桌前。

### 输入框上面那一行工具：只给真排得出来的按钮

论坛那种两排（字体、字号、颜色、对齐、表情……）**不做**。两条理由：

1. **排不出来的按钮是骗人的。** 我们的 `mdRender()` 认这些：标题、粗体、斜体、行内代码、代码块、引用、无序/有序列表、表格、`[[双链]]`。上面那行工具**只给这 9 个 + 图片**。给一个点了没反应的按钮，比不给更坏。
2. **不做富文本。** 那一行做的是"把 markdown 符号插到光标处"，输入框里始终是**纯文本**。换成 contenteditable 富文本，你粘贴进来的东西会变成 HTML 标签 —— 那就违反了"你写的原文一字不动"。

选中几个字再点 = 包住那几个字；没选中 = 光标停在两个符号中间。改已存的那篇时，编辑框上也有同一排。

### 列表行：三层字号，标题必须压得住正文

原来列表行是「11px 元信息 / **13px** 标题(500) / **12.5px** 正文」—— **标题和正文只差 0.5px、字重只差半档**，扫过去就是一整片灰字，一条都抓不住。改后：

| 层 | 字号 / 字重 / 颜色 | 说明 |
|---|---|---|
| 元信息（时间·字数·标签） | 11px / 400 / `--ink3` 最浅 | 扫读时第一眼不看它 |
| **标题** | **15px / 600 / `--ink` 最深** | 加粗 + 加大 + 最深，三条一起才叫"一眼分得出" |
| 正文预览 | 13px / 400 / `--ink2` | 行高 1.75，够松 |

- **没标题的那条，把正文第一句提出来当标题**（断在句号上，不硬切 26 字）。原来没标题就只剩两行灰字 —— 那是全列表最平的一条。示例里 s1/s2/s3 也补上了标题。
- **元信息行最多 4 个标签**，多出来的收进 `+N`（鼠标停上去看）。一摆满就是噪音。
- 行间距 9px → **13px**，加了 hover 底色和"当前打开那条"的水色底 —— 眼睛有落脚点。
- 详情页：标题输入 15px/500 → **17px/600**。

### 覆盖保护（2026-11-01 事故后补的）

「载入例子」以前会**一声不吭把你自己存的全部冲掉**（`S` 整个重写）。客人自己存的那批就是这么没的。现在三条：

1. **覆盖前先自动存一份备份**（键名 `wgs_v1_bak`，只留最近一次）。
2. **只要你这里有东西，载入前必须先问**，且默认选项是「并进去 —— 你存的都留着」。
